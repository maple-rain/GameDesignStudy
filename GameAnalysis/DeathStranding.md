# Death Stranding

> 분석 기록: [TIL - 이동을 다음 콘텐츠로 가는 수단이 아니라 핵심 액션으로](../TIL/2026/09-09-DeathStranding.md)

근거 표기는 [Shadow Tactics](./ShadowTactics.md)에서 정한 3단계를 쓴다.

| 표기 | 근거 | 3단계 중 |
|---|---|---|
| `관찰` | 게임에서 실제로 일어나는 것 | ① 관찰 |
| `추론` | 왜 그렇게 만들었을지에 대한 가설. 확정된 결론이 아니다 | ② 설계적 추론 |
| `자료` | 개발자 발언이나 공식 자료로 확인된 것 | ③ 외부 근거 |

이 문서에도 `자료` 표기는 없다.

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 장르 | 오픈월드 액션 (실질적으로는 **물류**) |
| 중심 행동 | 전투가 아니라 **이동** `관찰` |
| 지형 | 배경이 아니라 해결해야 할 문제 `관찰` |
| 인벤토리 | 개수가 아니라 **무게와 부피를 가진 물리적 짐** `관찰` |
| 성장 | 능력치가 아니라 **인프라** `관찰` |
| 멀티 | 비동기 — 내가 설치한 구조물이 남의 게임에 나타난다 `관찰` |

세 번째와 네 번째가 이 게임의 출발점이다. `추론`

**지형을 문제로 만들고 인벤토리를 물리로 만들면, 걷는 것만으로 게임이 성립한다.**
둘 중 하나만 있으면 그냥 불편한 오픈월드가 된다.

## 2. Core Experience

> 목적지까지 가는 것이 아니라, **어떤 경로로 어떻게 갈 것인가를 계속 푸는 것** `추론`

이 게임이 바꾼 것은 콘텐츠가 아니라 **액션의 대상**이다. `추론`

| | 이동의 역할 |
|---|---|
| 일반적인 액션 게임 | 이동 → 전투 → 이벤트 → 이동 — **연결 통로** |
| **Death Stranding** | 이동 → 지형 문제 → 장비 → 경로 → 화물 관리 → 인프라 — **본론** |

기존 액션 게임의 틀을 버린 것이 아니라, **그 틀의 중심에 다른 행동을 놓았다.** `추론`

## 4. 핵심 메커닉 분석

### 행동 메커닉 `관찰`

걷기 · 달리기 · 점프 · 등반 · 화물 운반 · 장비 사용 ·
차량 이용 · 로프 및 사다리 설치 · 구조물 설치

목록 자체는 특별하지 않다. `관찰`
**특별한 것은 이 행동들이 전부 하나의 문제(이동)로 수렴한다는 점이다.** `추론`

```
지형을 확인 → 건널 수 있는 위치 판단 → 사다리 / 앵커 사용
→ 화물 균형 유지 → 이동
```

### 시스템 메커닉 `관찰`

지형 · 화물의 무게와 부피 · 무게 중심과 균형 · 화물 손상 ·
장비와 구조물 · 차량과 도로와 집라인 · 배송 평가 · 비동기 멀티플레이 · MULE과 BT

### 메커닉 언어화 — 화물

| 단계 | 내용 |
|---|---|
| 행동 | 배송할 짐과 장비를 몸에 싣는다 |
| 규칙 | 무게와 부피가 있고, 무게 중심이 무너지면 균형을 잃으며 넘어지면 손상된다 `관찰` |
| 결과 | 인벤토리가 **숫자가 아니라 배치의 문제**가 된다 `추론` |
| 감정 | 이만큼 실어도 갈 수 있을까 `추론` |

**인벤토리를 물리로 만들면 소지품 관리가 이동의 일부가 된다.** `추론`

```
인벤토리가 목록이다  → 출발 전에 한 번 정하고 끝난다
인벤토리가 물리다    → 걷는 내내 그 결정의 결과를 받는다
```

### 메커닉 언어화 — 배송 평가

| 단계 | 내용 |
|---|---|
| 행동 | 배송을 완료한다 |
| 규칙 | 도착 여부만이 아니라 효율과 화물 보존 상태가 평가된다 `관찰` |
| 결과 | 목표가 `도착`에서 **`어떻게 도착하는가`**로 바뀐다 `추론` |
| 감정 | 그냥 가면 되는 게 아니구나 `추론` |

[Devil May Cry 5](./DevilMayCry5.md)의 스타일 랭크와 같은 계열이다. `추론`
그쪽은 **전투의 내용**을 평가했고, 이쪽은 **이동의 내용**을 평가한다.

그리고 이 평가가 전투를 억제한다. `추론`
싸우면 시간과 화물 상태에서 손해가 나므로, **전투가 항상 최선이 아니게 된다.**

| 행동 | 불편한 구간에 사다리나 로프를 설치한다 |
| 규칙 | 그 자리에 남고, **다른 플레이어의 게임에도 나타날 수 있다** `관찰` |
| 결과 | 문제 해결이 **지형에 기록된다** `추론` |

## 5. 핵심 자원 (Core Resource)

### 1차 자원 — 몸에 실을 수 있는 적재량 `추론`

이 게임에서 항상 부족한 것은 시간도 체력도 아니다.
**한 번에 지고 갈 수 있는 양**이다.

특이한 것은 **이 한 칸을 목적과 수단이 나눠 쓴다**는 점이다. `관찰`

| 무엇을 싣는가 | 성격 |
|---|---|
| 화물 | **목적** — 이걸 나르려고 가는 것이다 |
| 장비 (사다리 · 앵커 등) | **수단** — 이걸로 나르기 쉬워진다 |

```
장비를 챙긴다 → 이동이 쉬워진다 → 그런데 그 장비도 짐이다
장비를 뺀다   → 화물을 더 실을 수 있다 → 그런데 험지에서 막힌다
```

> **문제를 푸는 도구가 문제의 일부다.** `추론`

이 구조 덕분에 출발 전 준비가 그 자체로 판단이 된다.
장비를 무한히 챙길 수 있다면 지형은 더 이상 문제가 아니게 된다.

[DEATHLOOP](./Deathloop.md)에서 본 형태와 같은 계열이다. `추론`

| 게임 | 하나의 자원을 나눠 쓰는 두 용도 |
|---|---|
| DEATHLOOP | 정찰과 실행이 **시간대 슬롯**을 나눠 쓴다 |
| **Death Stranding** | 화물과 장비가 **적재량**을 나눠 쓴다 |

### 그리고 이 자원은 스칼라가 아니다

무게뿐 아니라 **무게 중심**이 있다. `관찰`

같은 양이라도 어떻게 실었느냐에 따라 결과가 달라지므로,
**자원의 양과 자원의 배치가 별개의 문제가 된다.** `추론`

> 대부분의 게임에서 소지 한도는 숫자 하나다. 여기서는 **형태를 가진다.**

### 축적 자원 — 지형에 남는 인프라 `관찰`

이 게임에서 성장은 능력치가 아니다.

```
불편한 이동 경험 → 문제 발견 → 장비 · 인프라 확보
→ 이동 방식 개선 → 더 효율적인 배송 → 더 큰 배송
```

도보 → 장비 → 차량 → 도로와 집라인으로 이동 수단이 바뀌면서,
**같은 지역이 갈수록 쉬워진다.** `관찰`

### 이 축적 자원은 저장소에서 처음 나오는 형태다

지금까지 본 축적 자원과 놓이는 자리가 다르다. `추론`

| 게임 | 축적되는 것 | 어디에 쌓이는가 |
|---|---|---|
| [Monster Hunter: World](./MonsterHunterWorld.md) | 몬스터에 대한 지식 | 플레이어의 머릿속 |
| [Hitman](./Hitman.md) · [DEATHLOOP](./Deathloop.md) | 맵과 시간표에 대한 지식 | 플레이어의 머릿속 |
| **Death Stranding** | **인프라** | **지형 — 그리고 남의 세계에도** |

머릿속에 쌓이는 지식은 옮길 수 없지만, **지형에 쌓인 해결은 남이 그대로 쓸 수 있다.** `추론`
10번에서 다루는 비동기 멀티플레이가 성립하는 이유가 여기에 있다.

### 근거의 범위

| 항목 | 근거 |
|---|---|
| 화물에 무게와 부피가 있고 균형이 무너지면 넘어진다 | `관찰` |
| 장비를 챙기면 이동이 쉬워지지만 운반량이 늘어난다 | `관찰` |
| 설치한 구조물이 남고 다른 플레이어에게도 나타난다 | `관찰` |
| 핵심 자원을 `적재량`으로, 그 안에서 목적과 수단이 경쟁한다고 보는 해석 | `추론` — 장비의 이중성에서 역산했다 |
| 실제 적재 한도, 균형 판정의 기준, 구조물 공유 규칙 | **미검증** |

> **검증 방법**: 같은 배송을 장비 없이 한 번, 장비를 최대한 챙겨 한 번 수행하고 소요 시간과 화물 손상률을 비교한다. 장비를 챙긴 쪽이 항상 유리하다면 `수단도 짐이다`라는 긴장은 성립하지 않는다.

```
[한 번의 배송]                     [게임 전체]
배송 의뢰 확인                     불편한 이동 경험
  ↓                                  ↓
화물 · 장비 준비                    문제 발견
  ↓                                  ↓
지형 확인 → 경로 선택               장비 · 인프라 확보
  ↓                                  ↓
이동 → 장애물 대응                  이동 방식 개선
  ↓                                  ↓

```

두 루프의 관계가 이 게임의 진행을 만든다. `추론`

그래서 이 게임의 성장은 `강해지는 것`이 아니라 **`아까 힘들었던 곳을 고치는 것`**이다.

## 7. Problem Chaining

이 게임의 체인에는 다른 게임에 없는 성질이 있다. **해결이 영구적으로 남는다.** `추론`

```
이 산을 어떻게 넘지
  ↓
사다리를 설치한다
  ↓
넘어간다 — 그리고 사다리는 그 자리에 남는다
  ↓
다음에 이 길로 올 때는 문제가 아니다
  ↓
더 먼 곳, 더 무거운 화물이 새 문제가 된다
```

[Resident Evil 2](./ResidentEvil2.md)와 정확히 거울상이다. `추론`

| 게임 | 그 자리에 남는 것 |
|---|---|
| Resident Evil 2 | **미룬 문제** — 지나친 좀비는 계속 거기 있다 |
| **Death Stranding** | **해결한 결과** — 설치한 사다리는 계속 거기 있다 |

앞의 것은 회피에 값을 붙이고, 뒤의 것은 **해결에 이자를 붙인다.** `추론`

그리고 여기에 비동기 멀티가 겹치면 체인이 플레이어 한 명을 넘어간다. `관찰`

```
내가 불편을 겪는다 → 구조물을 세운다 → 남이 쓴다
→ 남이 또 다른 구조물을 세운다 → 이동 네트워크가 생긴다
```

**문제 체인이 여러 사람에게 분산되어 풀린다.** `추론`

## 8. 제거 / 변경 분석

### 전투 (MULE · BT)

배송 중에 전투가 발생하지만, 평가 시스템 때문에 **싸우는 것이 항상 최선은 아니다.** `관찰`
그렇다면 전투는 없어도 되는 요소인가.

[Sleeping Dogs](./SleepingDogs.md)의 5개 층위와 [BioShock Infinite](./BioShockInfinite.md)의 중심축 검사를 적용한다.

| 층위 | 해당 여부 |
|---|---|
| 핵심 게임플레이 | **부분적으로** — 위험이 경로 선택의 변수가 된다 |
| 성장 시스템 | 아니다 |
| 공간 / 세계 경험 | 그렇다 — 지역마다 위험의 성격이 다르다 |
| 장식 / 분위기 | 그렇다 |

중심축 검사를 대면 자리가 분명해진다. `추론`

이 게임의 중심축은 `이동을 문제로 만드는 것`이다.
전투는 그 문제에 **지형 외의 변수를 하나 더 얹는 장치**다.

```
지형만 있다   → 경로 문제가 정적이다 (지도만 보면 답이 나온다)
위험이 있다   → 같은 경로라도 시점과 상황에 따라 답이 달라진다
```

**따라서 전투는 제거 후보가 아니라 리듬 장치다.** `추론`
13번에서 정리한 `초 · 중 · 후반의 변주`와 같은 역할이며,
평가 시스템이 전투를 억제하기 때문에 **전투가 있어도 중심축이 이동에서 벗어나지 않는다.**

> 두 시스템이 서로를 잡아 준다. 전투는 변수를 만들고, 평가는 그 변수가 주인공이 되지 못하게 막는다. `추론`

### 남은 검증

| 항목 | 상태 |
|---|---|
| 전투를 전부 회피하는 플레이가 실제로 성립하는가 | **미검증** |

> **검증 방법**: 한 챕터를 전투 없이 회피만으로 진행해 본다. 성립한다면 전투는 선택지이고, 강제되는 구간이 있다면 그만큼은 중심축에서 벗어난 콘텐츠다.

**오늘 분석에서 명확한 제거 후보는 찾지 못했다.**
이 게임은 거의 모든 시스템이 `이동`이라는 한 층에 붙어 있어서, 떼어낼 것이 적다. `추론`

- 배송 이후 NPC가 후일담을 전한다 `관찰`

**② 설계적 추론**

> 이동을 다음 콘텐츠로 가는 통로가 아니라 **그 자체로 푸는 문제**로 만드는 것. `추론`

여섯 관찰이 하나로 모인다.

| 설계 | 그 결과 |
|---|---|
| 지형을 문제로 만든다 | 경로 선택이 판단이 된다 |
| 인벤토리를 물리로 만든다 | 준비가 이동 내내 따라온다 |
| 장비도 짐으로 만든다 | 해결 수단에 값이 붙는다 |
| 도착 방식을 평가한다 | 목표가 `가는 것`에서 `어떻게 가는가`로 옮겨간다 |
| 구조물이 남는다 | 노력이 지형에 기록된다 |
| 후일담을 붙인다 | 반복되는 배송에 의미가 생긴다 |

**즉 이 게임이 설계한 것은 배송이 아니라 이동의 무게다.** `추론`

**③ 외부 근거**

없다. 따라서 ②는 여기서 멈춘다.

## 10. 기획자로서 배울 점

### ① 하나의 자원을 목적과 수단이 나눠 쓰게 한다

적재량이 그렇다. 화물은 목적이고 장비는 수단인데 같은 칸을 쓴다. `관찰`

> **문제를 푸는 도구에도 값을 붙이면, 준비 단계가 그 자체로 판단이 된다.** `추론`

장비를 무한히 챙길 수 있으면 지형은 문제가 아니게 된다.
**해결 수단을 무료로 두면 그 수단이 막으려던 문제도 같이 사라진다.**

### ② 인벤토리를 숫자가 아니라 물리로 만들 수 있다

| | 소지품 관리가 일어나는 시점 |
|---|---|
| 목록형 인벤토리 | 출발 전 한 번 |
| **물리형 인벤토리** | **이동하는 내내** |

무게 중심까지 넣으면 자원이 **양이 아니라 형태**를 갖는다. `추론`
같은 총량이라도 어떻게 실었는지가 결과를 바꾸므로, 판단이 한 겹 늘어난다.

### ③ 해결이 지형에 남으면 진행이 축적된다

[Resident Evil 2](./ResidentEvil2.md)와 거울상인 구조다.

```
미룬 문제가 남는다   → 회피에 값이 붙는다 → 언젠가 처리하게 된다
해결이 남는다        → 노력에 이자가 붙는다 → 다시 오는 것이 즐거워진다
```

**같은 지역을 다시 방문하는 것을 반복이 아니라 성과 확인으로 만들 수 있다.** `추론`

### ④ 남의 해결이 내 선택지가 되게 한다

비동기 멀티플레이의 핵심은 대결이 아니라 **흔적**이다. `추론`

```
혼자다      → 이 산을 어떻게 넘지
남이 있다   → 이미 누군가 길을 만들어두었네
```

여기서 중요한 것은 **내가 만든 것을 남이 쓴다는 사실이 설치의 동기가 된다**는 점이다. `관찰`
[Devil May Cry 5](./DevilMayCry5.md)에서 정리한 `관객이 있으면 설계가 바뀐다`와 같은 자리이며,
그쪽은 남이 **보는** 것이었고 이쪽은 남이 **쓰는** 것이다.

### ⑤ 평가가 도착이 아니라 도착 방식을 묻게 한다

배송 평가가 하는 일은 난이도 조절이 아니다. `추론`

**전투처럼 눈에 띄는 행동이 주인공이 되지 못하게 막는 장치다.**
싸우면 시간과 화물에서 손해가 나므로, 플레이어가 스스로 이동 쪽으로 돌아온다.

> 중심축을 지키는 방법은 다른 콘텐츠를 빼는 것이 아니라, **그것을 선택했을 때의 값을 매기는 것**이다. `추론`

### ⑥ 배경을 문제로 승격시킨다

[Sleeping Dogs](./SleepingDogs.md)에서 `배경을 자원으로 바꾸면 장소가 게임플레이가 된다`고 정리했다.
이 게임은 같은 일을 반대 방향으로 한다. `추론`

| 게임 | 배경에 한 일 |
|---|---|
| Sleeping Dogs | 배경을 **자원**으로 (환경 처형) |
| **Death Stranding** | 배경을 **문제**로 (지형) |

**둘 다 배경을 상호작용 대상으로 올렸고, 하나는 도구가 되고 하나는 장애물이 됐다.**

### ⑦ 핵심 행동은 유지하고 문제만 바꾼다

걷는다는 행동은 처음부터 끝까지 같다. `관찰`
바뀌는 것은 **그 걷기가 풀어야 하는 문제**다.

```
초반 — 지형과 화물
중반 — 차량과 장비
후반 — 도로와 집라인
그리고 그 위에 MULE · BT라는 변수
```

[Monster Hunter: World](./MonsterHunterWorld.md)의 `같은 행동의 반복 ≠ 같은 경험의 반복`이 여기서도 작동한다. `추론`
다만 그쪽은 **플레이어가 달라져서** 경험이 바뀌었고,
이쪽은 **문제가 달라져서** 바뀐다.
