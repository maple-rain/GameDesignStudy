# Possibility Space — 가능성의 공간

> **다루는 질문**: 플레이어가 만들었다고 느끼는 것은 정말 플레이어가 만든 것인가?
> 나온 곳: [Hades 분석](../GameAnalysis/Hades.md) (2026-08-11)

---

## 1. 정의

**개발자는 조합될 재료를 만들고, 플레이어는 그 재료로 자기 판을 조립한다.**

플레이어가 만드는 것은 완전히 새로운 무언가가 아니다.
개발자가 미리 깔아 둔 **가능성의 공간** 안에서

```
선택 → 조합 → 실험 → 발견 → 최적화
```

를 반복하는 것이다.

이 구분이 필요한 이유는, `플레이어가 빌드를 만든다`는 말이 자칫
**개발자가 아무것도 정하지 않았다**는 뜻으로 읽히기 때문이다. 그렇지 않다.

| 개발자가 정하는 것 | 플레이어가 정하는 것 |
|---|---|
| 재료의 종류와 성능 | 이번 판에 무엇을 집을 것인가 |
| 시너지의 존재 여부 | 지금 손에 든 것으로 어디까지 갈 것인가 |
| 등장 확률과 희귀도 | 방향을 유지할 것인가 갈아탈 것인가 |
| 조합의 상한과 하한 | 무엇을 목표로 삼을 것인가 |

---

## 2. 정답 빌드는 존재할 수밖에 없다

이 개념이 나온 계기는 **효율의 차이가 없는 게임이 더 좋은 게임인가**라는 질문이었다.

결론은 아니다.

- QA와 밸런싱을 거친 이상, 무엇이 더 효율적인지는 반드시 드러난다
- 모든 조합이 완전히 같으면 `뭘 골라도 똑같은데?`가 되어 **선택 자체가 의미를 잃는다**
- 플레이어 상당수는 공략을 원한다. `공략이 없는 것이 공략입니다`라는 답을 들으면 그 사람은 게임을 놓는다

**따라서 하나 이상의 의도적으로 강한 조합이 설계되어 있다고 보는 편이 자연스럽다.**

문제는 정답의 존재가 아니라 **정답이 게임을 끝내버리는가**다.

```
A + B = 압도적          →  플레이어는 공략을 찾고 A+B만 쓴다
A + B = 강함, A + C = 다른 방식으로 강함  →  상황에 따라 갈아탄다
전부 동일               →  고를 이유가 없다
```

**목표는 완벽한 균형이 아니라, 효율의 차이가 존재하면서도 다른 선택을 할 이유가 남아 있는 상태다.**

---

## 3. 공략은 적이 아니다

플레이어 입장에서 아래 두 문장은 완전히 다른 경험이다.

| | 플레이어가 하게 되는 일 |
|---|---|
| 이 게임에는 정답이 없다 | 아무거나 고른다. 고민이 사라진다 |
| **이 게임에는 내가 아직 발견하지 못한 강한 조합이 있다** | 찾는다. 실험한다. 확인한다 |

후자는 **발견 욕구**를 만든다.

```
발견 → 실험 → 성공 → 강력한 결과 확인 → 다음 조합 탐색
```

개발자가 강한 시너지를 일부러 숨겨 두는 것은 손해가 아니라 루프를 하나 더 만드는 일이다.
다만 그 시너지가 **압도적**이면 발견의 재미는 한 번으로 끝나고, 그 뒤로는 `그냥 A+B 쓰면 되는 게임`이 된다.

> 좋은 로그라이크의 목표는 공략을 없애는 것이 아니라
> **공략이 발견된 뒤에도 게임이 끝나지 않게 만드는 것**이다.

---

## 4. 분석 질문 다섯 개

로그라이크나 빌드형 게임을 분석할 때 순서대로 던진다.

```
① 개발자가 의도적으로 만들어 둔 강력한 조합은 무엇인가
② 그 조합을 플레이어가 얼마나 쉽게 발견할 수 있는가
③ 강력한 조합을 발견한 이후에도 다른 선택을 할 이유가 있는가
④ 실패한 조합도 다른 상황에서는 유효한가
⑤ 결국 하나의 정답 빌드로 수렴하는가
```

**④와 ⑤가 핵심이다.**
①②③은 게임이 무엇을 제공하는지를 묻지만, ④⑤는 **실제로 플레이어가 어떻게 되는지**를 묻는다.

④가 예이면 선택지는 상황 판단의 재료가 되고, 아니오이면 그냥 꽝이 된다.
⑤가 예이면 선택지의 개수가 아무리 많아도 실제 플레이의 다양성은 하나다.

## 5. 게임별 사례 비교

| 게임 | 플레이어가 만드는 것 | 수렴을 막는 장치 | 판정 |
|---|---|---|---|
| [Hades](../GameAnalysis/Hades.md) | 빌드 · 루트 · 플레이 방식 · 목표 | 신 4명 제한 · 희귀도 선행 조건 · 무기 24종 · 형벌 규약 | **공급을 좁혀서 막는다** `추론` |
| [Slay the Spire](../GameAnalysis/SlayTheSpire.md) | 덱 | 카드 제거와 미획득도 선택 · 캐릭터별 자원 구조 차이 | **덱을 줄이는 것도 성장이라 정답이 하나가 아니다** |
| [Vampire Survivors](../GameAnalysis/VampireSurvivors.md) | 무기 조합과 진화 경로 | 가변 보상 · 상자 여는 시점 조작 | **정답 조합이 비교적 뚜렷하다** |
| [Baba Is You](../GameAnalysis/BabaIsYou.md) | 규칙 자체 | 스테이지마다 해가 정해져 있다 | **해당 없음** — 만드는 대상이 다르다 |
| [Factorio](../GameAnalysis/Factorio.md) | 공장 | 정답 배치가 있어도 규모가 커지면 다시 문제가 생긴다 | **문제가 자기 설계에서 나와 수렴하지 않는다** |

### 여기서 보이는 것

**수렴을 막는 방법이 게임마다 다르다.**

| 방법 | 사례 |
|---|---|
| 재료의 공급을 좁힌다 | Hades — 원하는 신이 안 나온다 |
| 빼는 것도 성장으로 만든다 | Slay the Spire — 카드를 안 넣는 선택 |
| 문제 자체를 플레이어가 만들게 한다 | Factorio — 내 공장이 커져서 생긴 병목 |
| 목표를 플레이어가 정하게 한다 | Hades 형벌 규약 — 어디를 더 어렵게 할지 고른다 |

**Vampire Survivors는 이 장치가 가장 약하다.** 진화 조합이 명확하고 판이 길어질수록 최적해로 모인다.
같은 로그라이트인데도 반복 플레이의 수명이 다른 이유가 여기에 있다고 본다. `추론`

## 6. 분석 체크리스트

- [ ] 이 게임에서 플레이어가 **만들어내는 것**을 한 단어로 말할 수 있는가
- [ ] 그것을 만드는 재료는 무엇이고, 누가 정한 것인가
- [ ] 강한 조합이 존재하는가. 존재한다면 그것은 의도인가 사고인가
- [ ] 그 조합을 발견하는 과정 자체가 재미인가, 아니면 공략을 읽으면 끝나는가
- [ ] 발견 이후에도 다른 선택을 할 이유가 남는가
- [ ] 약한 선택지는 다른 상황에서 유효한가, 아니면 그냥 꽝인가
- [ ] **선택지의 개수**와 **실제 플레이의 다양성**을 따로 셌는가

마지막 항목이 이 문서의 핵심이다.
**선택지가 많다는 것과 선택이 다양하다는 것은 다른 문제다.**

---

## 7. 아직 확인하지 못한 것

이 개념은 Hades를 **직접 플레이하지 않고** 정리한 것이다.
따라서 아래는 검증 대상으로 남는다.

| 항목 | 왜 확인이 필요한가 |
|---|---|
| 실제로 어떤 빌드로 수렴하는가 | 자료상 강한 조합이 언급되지만, 실제 플레이 빈도는 확인하지 못했다 |
| 좁힌 공급이 재미인가 불쾌인가 | 원하는 신이 안 나오는 것이 변주로 느껴지는지, 손해로 느껴지는지는 겪어 봐야 안다 |
| 거울 강화의 선택이 실제로 다르게 느껴지는가 | 같은 시간축에서 비슷한 효율을 조절하는 항목이 있다 |

**Vampire Survivors와 Slay the Spire를 이 다섯 질문으로 다시 읽는 것이 다음 작업이다.**
두 게임은 이미 분석했지만, 그때는 `무엇이 재미있는가`만 물었고 `무엇으로 수렴하는가`는 묻지 않았다.
