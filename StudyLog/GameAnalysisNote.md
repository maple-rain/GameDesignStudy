# Game Analysis Study Note

게임 분석 과정에서 나온 생각, 고민, 발견을 기록하는 공간.

## 목적

이 문서는 포트폴리오용 결과물이 아니다.
게임을 분석하면서 발생한 **사고 과정과 학습 내용**을 그대로 기록한다.

| 폴더 | 성격 |
|---|---|
| [GameAnalysis](../GameAnalysis) | 다른 사람이 읽어도 이해되는 정리된 분석 |
| [TIL](../TIL) | 날짜별 학습 기록과 그날의 깨달음 |
| **StudyLog** | 정리되지 않은 사고 과정, 실패한 가설, 고민 |

기록 대상

- 처음 게임을 접했을 때의 생각
- 분석하면서 변경된 관점
- 발견한 메커닉
- 분석 과정에서 생긴 질문
- 실패한 분석
- 새롭게 배운 게임 설계 원칙

정리된 결과물만 있는 기록보다, **어떻게 생각하는 사람인지**가 남는 기록이 더 가치 있다고 판단해서 이 문서를 만들었다.

# Analysis Log

## Baba Is You

### 첫 인상

처음에는 단순한 퍼즐 게임이라고 생각했다.
"바바는 나? 나? 는 바?바" 정도로 제목만 보고 넘겼다.

하지만 분석하면서 이 게임의 핵심은 퍼즐 해결이 아니라 **규칙 자체를 조작하는 경험**이라는 점을 발견했다.

### 내가 발견한 재미 요소

#### 규칙 조작

대부분의 게임은 개발자가 만든 규칙을 플레이어가 따른다.
하지만 Baba Is You에서는 규칙 자체가 조작 대상이다.

'벽은 막는다'라는 상식을 '벽을 밀 수 있다', '벽이 플레이어가 된다'로 바꿀 수 있다.

#### 문제를 다시 정의하기

정답을 찾는 퍼즐이 아니었다.
현재 규칙을 의심하고, 새로운 규칙을 만들어 해결책을 찾는 구조였다.

### 분석하면서 생긴 질문

**Q. 규칙도 메커닉이라고 볼 수 있을까?**

처음에는 메커닉을 플레이어 행동이라고 생각했다.
하지만 이 게임에서는 시스템 규칙 변화 자체가 플레이 경험을 만든다.

이 질문이 이번 분석에서 가장 오래 붙잡고 있던 부분이었다.

### 실패한 분석

'없어도 되는 요소'를 찾으려고 계속 시도했다.

- 벽 → 규칙에 따라 플레이어가 될 수 있다
- 풀 → 목표가 될 수 있다
- 깃발 → 장애물이 될 수 있다

결국 하나도 떼어낼 수 없었다.
처음에는 내가 분석을 못한 것이라고 생각했지만,
**모든 게임에 반드시 '없어도 되는 요소'가 존재하는 것은 아니다**는 것이 결론이었다.

분석 도구(제거 테스트)가 절대적인 기준이 아니라는 것을 이 게임에서 처음 알게 되었다.

### 아직 남은 아쉬움

핵심이 '규칙을 바꾸고 그 규칙 자체가 게임이 되도록 하는 것'이라는 데까지는 도달했지만,
그것을 한 문장의 정의로 완전히 다듬는 단계까지는 가지 못했다.

메커닉을 찾는 것과 **게임의 핵심을 한 문장으로 정의하는 것**은 다른 능력이라는 걸 느꼈다.

### 최종 정리

**행동 메커닉**

- 이동
- 밀기
- 규칙 블록 이동

**시스템 메커닉**

- 규칙 생성
- 규칙 변경
- 규칙 삭제
- 규칙 충돌
- 규칙 우선순위
- 승리 조건 변경

이번 분석을 통해 시스템 메커닉의 범위를 다시 생각하게 되었다.

# Learned Concept

분석을 진행하면서 새로 알게 되거나 스스로 정리한 개념들.

| 개념 | 알게 된 계기 | 정리 |
|---|---|---|
| Core Mechanic | Portal 2 | 게임의 다른 요소를 모두 연결하는 중심 규칙 → [문서](../MechanicStudy/CoreMechanic.md) |
| Problem Chaining | Portal 2 | 한 질문에 답하면 다음 질문이 발생하도록 배치하는 설계 → [문서](../MechanicStudy/ProblemChaining.md) |
| Reward Loop | Vampire Survivors | 행동 → 보상 → 성장 → 새로운 목표의 반복 → [문서](../MechanicStudy/RewardLoop.md) |
| 메커닉 언어화 공식 | Vampire Survivors | `행동 → 규칙 → 결과 → 감정`. 가장 자주 빠뜨리는 항목은 '결과' |
| 가변 보상 | Vampire Survivors | 보상의 크기보다 확정되지 않은 상태의 기대감이 더 강한 자극을 만든다 |
| 확률 공간 조작 | Vampire Survivors | 플레이어는 규칙을 따르지 않고 역이용해 기대값을 높인다 |
| Resource Chaining | Celeste | 자원의 소비 지점과 회복 지점을 배치해 플레이어의 판단을 유도 |
| 규칙 지배감 | Celeste | 고급 테크닉의 재미는 속도가 아니라 규칙을 완전히 이해했다는 감각 |
| 개발 의도 ≠ 플레이 경험 | Hollow Knight | 같은 메커닉도 플레이어의 정보량과 환경에 따라 다른 감정이 된다 |
| 개인적 불편함 ≠ UX 문제 | Hollow Knight | "나는 불편했다"에서 멈추면 분석이 아니다 |
| Core Resource | Slay the Spire | 플레이어가 항상 부족하다고 느끼는 것. 메커닉 대부분이 이것을 중심으로 설계된다 |
| 덱 순환(Draw Cycle) | Slay the Spire | 카드를 추가하지 않는 선택과 제거하는 선택도 성장의 일부다 |
| 공략 ≠ 기획 분석 | Slay the Spire | 공략은 '어떻게 이기는가', 기획 분석은 '왜 이렇게 만들었는가' |
| System Mechanic | Baba Is You | 규칙 자체가 플레이 대상이 될 수 있다 |
| 반복 구조는 설계다 | INSIDE | 한 번은 우연이지만 반복되면 설계다 |
| 메타 분석 | Among Us | 시스템 → 플레이어의 최적화 → 새로운 메타 → 시스템의 재설계 |
| 게임 목표 / 플레이어 목표 | Factorio | 엔딩 이후에도 플레이가 이어지는 이유는 플레이어가 스스로 목표를 만들기 때문 |
| 분석 불가라는 결론 | Outer Wilds | 모든 게임이 같은 방식으로 분석되지는 않는다 |

# 스스로 점검하는 질문

- '결과' 항목을 비워두지 않았는가?
- 내 개인 취향과 UX 문제를 구분했는가?
- 개발 의도와 내 경험을 구분해서 적었는가?
- 처음 생각이 분석 중에 바뀐 지점을 기록했는가?
