# Learned Concepts

게임을 분석하면서 새로 알게 되거나 스스로 정리한 개념들.

각 개념이 **어느 게임에서 나왔는지**를 함께 기록한다.
개념을 먼저 배우고 게임에 적용한 것이 아니라, 게임을 분해하다가 필요해져서 만든 언어이기 때문이다.

---

## 개념 목록

| 개념 | 알게 된 계기 | 정리 |
|---|---|---|
| Core Mechanic | Portal 2 | 게임의 다른 요소를 모두 연결하는 중심 규칙 → [문서](../MechanicStudy/CoreMechanic.md) |
| Problem Chaining | Portal 2 | 한 질문에 답하면 다음 질문이 발생하도록 배치하는 설계 → [문서](../MechanicStudy/ProblemChaining.md) |
| UI도 메커닉이다 | Portal 2 | 상태를 읽을 수 없으면 메커닉이 작동하지 않는다 → [문서](../MechanicStudy/UXFeedback.md) |
| Reward Loop | Vampire Survivors | 행동 → 보상 → 성장 → 새로운 목표의 반복 → [문서](../MechanicStudy/RewardLoop.md) |
| 메커닉 언어화 공식 | Vampire Survivors | `행동 → 규칙 → 결과 → 감정`. 가장 자주 빠뜨리는 항목은 '결과' |
| 가변 보상 | Vampire Survivors | 보상의 크기보다 확정되지 않은 상태의 기대감이 더 강한 자극을 만든다 |
| 확률 공간 조작 | Vampire Survivors | 플레이어는 규칙을 따르지 않고 역이용해 기대값을 높인다 |
| 시스템 결과 / 플레이 결과 | Vampire Survivors | `아이템 레벨 +1`과 `빌드 방향이 고정된다`는 다른 층위다 |
| Resource Chaining | Celeste | 자원의 소비 지점과 회복 지점을 배치해 플레이어의 판단을 유도 |
| 규칙 지배감 | Celeste | 고급 테크닉의 재미는 속도가 아니라 규칙을 완전히 이해했다는 감각 |
| 캐릭터가 UI가 된다 | Celeste | 플레이어의 시선이 이미 가 있는 곳에 정보를 둔다 |
| 개발 의도 ≠ 플레이 경험 | Hollow Knight | 같은 메커닉도 플레이어의 정보량과 환경에 따라 다른 감정이 된다 |
| 개인적 불편함 ≠ UX 문제 | Hollow Knight | "나는 불편했다"에서 멈추면 분석이 아니다 |
| 불편함이 메커닉일 수 있다 | Hollow Knight | 지도의 제약이 공간 기억을 만든다. 개선 전에 그 불편이 뭘 만드는지 확인 |
| 분석 불가라는 결론 | Outer Wilds | 모든 게임이 같은 방식으로 분석되지는 않는다 |
| 소모 자원 / 축적 자원 분리 | Outer Wilds | 실패해도 남는 자원이 있으면 실패가 손실이 아니라 획득이 된다 |
| 메커닉 ≠ 재미 요소 | Papers, Please | 뇌물은 메커닉이고, 생계와 양심 사이의 고민이 재미 요소다 |
| 초회차 / 반복 플레이 분리 | Papers, Please | 초회차의 장점이 반복 플레이의 단점이 될 수 있다 |
| 반복 구조는 설계다 | INSIDE | 한 번은 우연이지만 반복되면 설계다 |
| 플레이 필수 / 경험 강화 구분 | INSIDE | 병아리는 필수가 아니지만 몰입을 만든다 |
| 실패 비용과 학습의 관계 | INSIDE | 설명을 생략하려면 실패 비용을 함께 낮춰야 한다 → [문서](../MechanicStudy/FailureDesign.md) |
| 장르 문법은 무료 튜토리얼 | INSIDE | 리틀 나이트메어를 안다면 설명 없이도 위험을 판단한다 |
| Core Resource | Slay the Spire | 플레이어가 항상 부족하다고 느끼는 것. 메커닉 대부분이 이걸 중심으로 설계된다 |
| 덱 순환 (Draw Cycle) | Slay the Spire | 카드를 추가하지 않는 선택과 제거하는 선택도 성장의 일부다 |
| 공략 ≠ 기획 분석 | Slay the Spire | 공략은 '어떻게 이기는가', 기획 분석은 '왜 이렇게 만들었는가' |
| 정보 체이닝 | Return of the Obra Dinn | 정보를 수집하는 게임과 정보를 연결하는 게임은 다르다 |
| 처벌 없이 신중함 만들기 | Return of the Obra Dinn | 오답을 처벌하지 않으면서 확정 조건을 묶어 찍기를 막는다 |
| 직업 설정이 목표를 규정한다 | Return of the Obra Dinn | 탐정이 아니라 보험 조사관이라 '기록'이 목적이 된다 |
| System Mechanic | Baba Is You | 규칙 자체가 플레이 대상이 될 수 있다 |
| 제거 테스트의 한계 | Baba Is You | 모든 게임에 '없어도 되는 요소'가 존재하는 것은 아니다 |
| 메커닉 / 경험 / 감정 / 개발 의도 | Factorio | 4개 층위를 구분하지 않으면 수단을 의도로 착각한다 |
| 게임 목표 / 플레이어 목표 | Factorio | 엔딩 이후에도 플레이가 이어지는 이유 |
| 자원을 유량으로 설계하기 | Factorio | 부족함을 속도로 만들면 해결책이 '모으기'에서 '구조 바꾸기'가 된다 |
| 문제가 아니라 문제 발생 규칙 | Factorio | 플레이어의 문제가 자기 설계에서 나오면 난이도가 자동 조절된다 |
| 튜토리얼 위장 | The Witness | 튜토리얼을 없앤 것이 아니라 난이도 순 배치로 위장한 것 |
| 취향 / UX 문제 판정 | The Witness | 내가 싫어한 요소가 반드시 설계 결함인 것은 아니다 |
| 메타 분석 | Among Us | 시스템 → 플레이어의 최적화 → 새로운 메타 → 시스템의 재설계 |
| 자원의 소유자 | Among Us | 신뢰는 내가 가진 자원이 아니라 다른 플레이어가 나에게 주는 자원 |
| 탈락자 설계 | Among Us | 죽은 뒤에도 할 일과 선택권이 있어야 이탈하지 않는다 |
| 의미 있는 선택 ≠ 선택지 개수 | Disco Elysium | 결과가 같아도 정보·관계·성격·후속 대화 중 하나를 바꾸면 살아 있는 선택이다 |
| 실패의 서사화 | Disco Elysium | 처벌을 없애는 것과 실패에 별도의 내용을 주는 것은 다른 설계다 → [문서](../MechanicStudy/FailureDesign.md) |
| 메커닉 층위의 경계 | Disco Elysium | 행동의 종류가 아니라 게임이 그 행동을 어떤 규칙으로 처리하는가로 판단한다 |
| 자원 배분이 인격이 된다 | Disco Elysium | 하나의 스킬 수치가 **능력치와 들리는 목소리를 동시에** 정한다. 올리면 강해지는 게 아니라 그런 사람이 된다 |

## 분석하면서 바뀐 생각들

기록으로 남길 가치가 있는 것은 결론보다 **판단이 바뀐 지점**이다.

| 게임 | 처음 생각 | 바뀐 생각 |
|---|---|---|
| Portal 2 | 포탈 건이 재미있는 건 순간이동이라는 SF적 장치 때문 | 공간 인식을 바꾸고 실험하게 만드는 장치라서 |
| Portal 2 | 스토리는 없어도 된다 | 퍼즐을 푸는 이유와 목적성을 부여한다 |
| Vampire Survivors | 성장 체감은 데미지 숫자에서 온다 | 화면 점유율과 시각적 영향력 확장에서 온다 |
| Vampire Survivors | 상자를 아껴 여는 건 그냥 내 습관 | 확률 공간을 조작하는 최적화 행동이었다 |
| Celeste | 대시는 빠르게 이동하는 기술 | 한 번 쓰면 조건까지 못 쓰는 제한 자원 |
| Celeste | 스피드런 기술은 고인물 꼼수 | 규칙을 극한까지 이해한 결과물 |
| Hollow Knight | 지도 시스템은 불편해서 없어도 된다 | 공간을 기억하게 만드는 탐험 메커닉이다 |
| Hollow Knight | 내가 막힌 건 게임 구조 문제 | 번역이 없던 플레이 환경의 문제였다 |
| Outer Wilds | 분석을 더 보충해야 한다 | 이 방법으로는 분석할 수 없다는 게 결론이다 |
| Papers, Please | 분기 인물 등장 시점을 모르는 건 단점 | 초회차엔 장점, 반복 플레이엔 아쉬움 |
| INSIDE | 병아리 디테일은 없어도 된다 | 플레이 필수는 아니지만 몰입을 만든다 |
| Slay the Spire | 얇은 덱이 그냥 좋은 것 | 좋은 카드를 더 자주 보기 위한 것 |
| Obra Dinn | 1비트 흑백은 없어도 되는 연출 | 정보량을 줄여 단서에 집중시키는 장치 |
| Baba Is You | 없어도 되는 요소를 못 찾은 건 내 분석이 부족해서 | 이 게임엔 그런 요소가 없을 수도 있다 |
| Factorio | 자동화 자체가 개발 의도 | 자동화는 수단이고, 내 설계가 작동하는 쾌감이 의도 |
| The Witness | 퍼즐의 재미를 전달하려는 게임 | 규칙을 발견하게 만드는 게임 |
| Among Us | 사보타지는 크루원을 분산시킨다 | 실제 메타에서는 오히려 뭉치게 만들었다 |
| Disco Elysium | 결과가 같은 선택지는 없어도 되는 요소다 | 결과 말고도 바뀌는 것이 있으면 살아 있는 선택이다 |

## 스스로 점검하는 질문

분석을 마쳤을 때 아래 질문에 답할 수 있는지 확인한다.

- 이 게임의 핵심 경험을 한 문장으로 말할 수 있는가?
- 메커닉을 나열한 것에서 끝나지 않고 감정까지 연결했는가?
- `행동 → 규칙 → 결과 → 감정` 중 '결과' 칸을 비워두지 않았는가?
- 핵심 자원을 특정했는가?
- 내 개인 취향과 UX 문제를 구분했는가?
- 개발 의도와 내 경험을 구분해서 적었는가?
- 처음 생각이 분석 중에 바뀐 지점을 기록했는가?
- 이 게임을 이 방법으로 분석하는 것이 적절했는가?
