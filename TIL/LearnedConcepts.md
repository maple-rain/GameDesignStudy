# Learned Concepts

게임을 분석하면서 새로 알게 되거나 스스로 정리한 개념들.

각 개념이 **어느 게임에서 나왔는지**를 함께 기록한다.
개념을 먼저 배우고 게임에 적용한 것이 아니라, 게임을 분해하다가 필요해져서 만든 언어이기 때문이다.

---

| 불편함이 메커닉일 수 있다 | Hollow Knight | 지도의 제약이 공간 기억을 만든다. 개선 전에 그 불편이 뭘 만드는지 확인 |
| 분석 불가라는 결론 | Outer Wilds | 모든 게임이 같은 방식으로 분석되지는 않는다 |
| 소모 자원 / 축적 자원 분리 | Outer Wilds | 실패해도 남는 자원이 있으면 실패가 손실이 아니라 획득이 된다 |
| 메커닉 ≠ 재미 요소 | Papers, Please | 뇌물은 메커닉이고, 생계와 양심 사이의 고민이 재미 요소다 |
| 초회차 / 반복 플레이 분리 | Papers, Please | 초회차의 장점이 반복 플레이의 단점이 될 수 있다 |
| 반복 구조는 설계다 | INSIDE | 한 번은 우연이지만 반복되면 설계다 |
| 플레이 필수 / 경험 강화 구분 | INSIDE | 병아리는 필수가 아니지만 몰입을 만든다 |
| 실패 비용과 학습의 관계 | INSIDE | 설명을 생략하려면 실패 비용을 함께 낮춰야 한다 → [문서](../MechanicStudy/FailureDesign.md) |
| 장르 문법은 무료 튜토리얼 | INSIDE | 리틀 나이트메어를 안다면 설명 없이도 위험을 판단한다 |
| Core Resource | Slay the Spire | 플레이어가 항상 부족하다고 느끼는 것. 메커닉 대부분이 이걸 중심으로 설계된다 |
| 덱 순환 (Draw Cycle) | Slay the Spire | 카드를 추가하지 않는 선택과 제거하는 선택도 성장의 일부다 |
| 공략 ≠ 기획 분석 | Slay the Spire | 공략은 '어떻게 이기는가', 기획 분석은 '왜 이렇게 만들었는가' |
| 정보 체이닝 | Return of the Obra Dinn | 정보를 수집하는 게임과 정보를 연결하는 게임은 다르다 |
| 처벌 없이 신중함 만들기 | Return of the Obra Dinn | 오답을 처벌하지 않으면서 확정 조건을 묶어 찍기를 막는다 |
| 직업 설정이 목표를 규정한다 | Return of the Obra Dinn | 탐정이 아니라 보험 조사관이라 '기록'이 목적이 된다 |
| System Mechanic | Baba Is You | 규칙 자체가 플레이 대상이 될 수 있다 |
| 제거 테스트의 한계 | Baba Is You | 모든 게임에 '없어도 되는 요소'가 존재하는 것은 아니다 |
| 메커닉 / 경험 / 감정 / 개발 의도 | Factorio | 4개 층위를 구분하지 않으면 수단을 의도로 착각한다 |
| 게임 목표 / 플레이어 목표 | Factorio | 엔딩 이후에도 플레이가 이어지는 이유 |
| 자원을 유량으로 설계하기 | Factorio | 부족함을 속도로 만들면 해결책이 '모으기'에서 '구조 바꾸기'가 된다 |
| 문제가 아니라 문제 발생 규칙 | Factorio | 플레이어의 문제가 자기 설계에서 나오면 난이도가 자동 조절된다 |
| 튜토리얼 위장 | The Witness | 튜토리얼을 없앤 것이 아니라 난이도 순 배치로 위장한 것 |
| 취향 / UX 문제 판정 | The Witness | 내가 싫어한 요소가 반드시 설계 결함인 것은 아니다 |
| 메타 분석 | Among Us | 시스템 → 플레이어의 최적화 → 새로운 메타 → 시스템의 재설계 |
| 자원의 소유자 | Among Us | 신뢰는 내가 가진 자원이 아니라 다른 플레이어가 나에게 주는 자원 |
| 탈락자 설계 | Among Us | 죽은 뒤에도 할 일과 선택권이 있어야 이탈하지 않는다 |
| 의미 있는 선택 ≠ 선택지 개수 | Disco Elysium | 결과가 같아도 정보·관계·성격·후속 대화 중 하나를 바꾸면 살아 있는 선택이다 |
| 실패의 서사화 | Disco Elysium | 처벌을 없애는 것과 실패에 별도의 내용을 주는 것은 다른 설계다 → [문서](../MechanicStudy/FailureDesign.md) |
| 메커닉 층위의 경계 | Disco Elysium | 행동의 종류가 아니라 게임이 그 행동을 어떤 규칙으로 처리하는가로 판단한다 |
| 자원 배분이 인격이 된다 | Disco Elysium | 하나의 스킬 수치가 **능력치와 들리는 목소리를 동시에** 정한다. 올리면 강해지는 게 아니라 그런 사람이 된다 |
| 가능성의 공간 | Hades | 개발자는 재료를 만들고, 플레이어는 그 안에서 `선택 → 조합 → 실험 → 발견 → 최적화`를 한다 → [문서](../MechanicStudy/PossibilitySpace.md) |
| 선택지의 개수 ≠ 선택의 다양성 | Hades | 선택지를 많이 주는 것과 서로 다른 선택이 각각 유효한 것은 다른 문제다 |
| 정답 빌드는 있어야 한다 | Hades | 전부 비등비등하면 고를 이유가 사라진다. 문제는 정답의 존재가 아니라 **정답이 게임을 끝내는가**다 |
| 시스템은 개수가 아니라 시간축으로 센다 | Hades | 스펙업 요소가 많아 보일 때는 줄이기 전에 **시간축이 겹치는 것**부터 찾는다 |
| 플레이어가 만들어내는 것 | Hades | `무엇이 재미있는가`에서 `플레이어는 무엇을 만드는가`로 질문을 옮기면 분석이 한 층 깊어진다 |
| 보스가 곧 스테이지다 | 완다와 거상 | 보스·레벨 디자인·퍼즐을 한 오브젝트에 겹치면 플레이어가 보스를 공략 대상이 아니라 **지형**으로 읽는다 |
| 시스템의 존재 ≠ 그 시스템이 만드는 경험 | 완다와 거상 | 자료로 확인되는 것은 존재까지다. 그것이 어떤 판단과 감정을 만드는지는 따로 검증해야 한다 |
| 자료 신뢰도 4단계 | 완다와 거상 | `직접 플레이 / 영상 / 문서 / 추론`을 섞어서 확인된 사실처럼 쓰지 않는다. 미확인 칸은 비우되 **검증 방법을 함께 적는다** |
| 연출과 조작권의 충돌 | 완다와 거상 | 문제는 시네마틱 카메라 자체가 아니라, 연출이 플레이어의 조작권을 가져가는 상황이다 |
| 대상을 크게 만드는 것은 플레이어의 한계다 | 완다와 거상 | 적의 크기를 키우면 큰 적이 되고, 플레이어 쪽 자원(악력)에 한계를 두면 **큰 문제**가 된다 |
| 플레이어가 만드는 것의 종류 | Devil May Cry 5 | Hades는 **빌드**를, DMC 5는 **플레이 스타일**을 만든다. 같은 질문이라도 만들어지는 대상이 다르다 |
| 숙련도의 외부화 | Devil May Cry 5 | 스타일 랭크는 보상이 아니라 **지표**다. 측정되지 않는 숙련은 성장으로 체감되지 않는다 |
| 평가 대상이 결과가 아니라 내용일 때 | Devil May Cry 5 | 처치 여부가 아니라 전투의 내용을 평가하면, 이겨도 만족스럽지 않게 만들어 다음 시도를 부른다 |
| 관객이 있으면 설계가 바뀐다 | Devil May Cry 5 | 남이 내 플레이를 본다는 전제 하나가 소모품 목록을 정리했다. 기준이 성능이 아니라 **흐름을 끊는가**로 바뀐다 |
| 제거는 개발사가 이미 했다 | Devil May Cry 5 | 시리즈가 길면 없어도 되는 요소는 이미 지워진 뒤다. `무엇을 지울까`가 아니라 **`무엇을 왜 지웠나`**를 본다 |
| 플레이어가 만드는 것 — 작전 | Shadow Tactics | 적의 행동·지형·캐릭터 능력을 조합한 `누가 · 언제 · 어떤 순서로`의 배열. **게임 안에 남지 않아도 만들었다는 감각은 성립한다** |
| 캐릭터가 아니라 플레이어가 강해진다 | Shadow Tactics | 반복의 산출물이 성장 수치가 아니라 규칙과 공간에 대한 이해일 수 있다. 수치 성장 없이도 난이도 곡선이 성립한다 |
| 메커닉 / 시스템 변수 / 버그 구분 | Shadow Tactics | 예측 가능하면 메커닉, 예측은 못 해도 목적이 보이면 시스템 변수, 둘 다 아니면 결함이다. **모든 이상 현상을 설계로 읽으면 없는 의도를 만들어낸다** |
| 개발자 의도 3단계 | Shadow Tactics | `① 관찰 → ② 설계적 추론 → ③ 외부 근거`. ③이 없으면 ②에서 멈추고 사실로 기록하지 않는다 |
| 외부 정보는 관찰보다 늦게 들여온다 | Shadow Tactics | 개발사의 평판을 먼저 알면 어떤 설계든 그 방향으로 읽힌다. 편견은 못 없애도 **무엇을 알고 시작했는지는 적어 둘 수 있다** |
| 액션의 퍼즐화 | Katana ZERO | 적·지형·능력·제약을 이용해 플레이어가 해결 방법을 설계하게 만들면, 장르가 액션이어도 전투가 **하나의 문제**가 된다 |
| 즉사는 난이도가 아니라 회전 속도다 | Katana ZERO | `즉사 + 긴 재시작`은 처벌이지만 `즉사 + 즉시 재시작`은 학습이다. 손잡이는 피격 판정이 아니라 **재시작 지연** 쪽에 있다 |
| 제약이 조합을 만든다 | Katana ZERO | 수단을 많이 주면 제일 센 것 하나만 쓴다. 가용 조건을 제한해야 질문이 `무엇이 센가`에서 **`가진 것으로 어떻게 푸는가`**로 바뀐다 |
| 플레이어가 만드는 것 — 해결 방법 | Katana ZERO | 만들어지는 것이 결과(적 처치)가 아니라 **과정**이다. 같은 방에 성립하는 해법이 몇 개인지가 설계 지표가 된다 |
| 규칙은 무엇을 지우는가로 본다 | Katana ZERO | 제한 시간이 지운 것은 시간이 아니라 **기다리는 플레이**다. 시스템을 넣을 때 `무엇을 제한하는가`가 아니라 `어떤 플레이를 지우는가`를 묻는다 |
| 취향은 제거 판정의 근거가 아니다 | Katana ZERO | `싫다`는 나에 대한 사실, `기능이 없다`는 게임에 대한 사실이다. **`게임플레이 기능이 없다`와 `기능이 없다`도 다르다** |
| 같은 행동의 반복 ≠ 같은 경험의 반복 | Monster Hunter: World | 좋은 반복 구조에서는 반복할 때마다 플레이어의 지식·숙련도·장비·목표·공략법이 변한다. **콘텐츠를 늘리지 않고 플레이 시간을 늘리는 방법** |
| 학습을 위한 반복 / 보상을 위한 반복 | Monster Hunter: World | 두 루프의 **종료 시점이 다르다.** 학습이 끝난 뒤의 반복은 도전이 아니라 노동이 된다 |
| 움직이는 문제 | Monster Hunter: World | 해결이 문제 자체를 변형시키는 구조. 부위를 파괴하면 몬스터의 행동이 바뀐다. 퍼즐과 달리 **정답이 하나가 아니다** |
| 최적해의 공개 여부가 창의성을 정한다 | Monster Hunter: World | 선택지가 많아도 최적해가 검색되면 플레이어는 만들지 않고 따라간다. **빌드 다양성 ≠ 플레이어의 창의성** |
| 수치 성장과 숙련 성장을 겹치기 | Monster Hunter: World | 둘을 한 행동에 얹으면 장비로 밀 수도, 숙련으로 뚫을 수도 있다. 난이도 폭이 넓어진다 |
| 넓은 맵은 정보를 놓아야 공간이 된다 | Monster Hunter: World | 흔적 조사가 없으면 같은 크기의 필드가 이동 시간으로만 남는다. 크기가 아니라 **놓인 정보의 양**이 탐색을 만든다 |
| 컨셉에 필요한 요소 ≠ 재미있는 요소 | Monster Hunter: World | 컨셉을 성립시키려고 넣은 장치가 핵심 재미를 밀어낼 수 있다. **컨셉 검증과 플레이 검증은 별도 절차다** |
| 오픈월드는 이유를 만드는 것이다 | Sleeping Dogs | 맵의 크기가 아니라 **돌아다닐 이유**가 오픈월드를 만든다. 발견 · 선택 · 반복 · 보상 네 가지로 확인한다 |
| 요소의 5개 층위 | Sleeping Dogs | 핵심 게임플레이 / 성장 시스템 / **공간·세계 경험** / UX / 장식·분위기. `없어도 돌아간다`로 판정하면 없애면 경험이 달라지는 요소를 놓친다 |
| 성장 축을 쪼개는 이유 | Sleeping Dogs | 삼합회는 `더 적극적으로 싸워라`, 경찰은 `덜 부수고 해라`. **요구가 반대이기 때문에** 축이 갈라진 것이다. 방향이 같으면 축이 아니라 이름만 여러 개다 |
| 배경을 자원으로 바꾸기 | Sleeping Dogs | 환경 처형은 벽과 유리창을 선택지로 승격시킨다. 장소를 기억에 남기는 방법은 잘 그리는 것이 아니라 **그 장소로 무언가를 하게 만드는 것** |
| 만드는 것이 없다는 결론도 분석이다 | Sleeping Dogs | 결과물을 만드는 게임과 경험을 축적하는 게임은 다르다. **후자를 전자의 기준으로 재면 저평가된다** |
| 판정을 단계로 쪼갠다 | Dishonored | 즉시 발각이면 들킨 뒤 할 수 있는 것이 도망뿐이다. **단계로 나누면 그 사이에 플레이어의 판단이 들어갈 자리가 생긴다** |
| 대가는 나중에 청구한다 | Dishonored | 금지하면 규칙을 지키고, 값을 붙이면 스스로 계산한다. 값이 **다음 미션**에서 청구되면 한 판이 아니라 회차 전체를 놓고 판단하게 된다 |
| 자유에는 대가를 같이 설계한다 | Dishonored | `자유 → 새로운 가능성 → 새로운 위험 → 다시 판단`. **위험 없는 선택지는 선택지가 아니라 정답이 된다** |
| 플레이어가 만드는 것 — 루트 | Dishonored | 정답이 아니라 자신만의 해결 방법. 재료는 개발자의 것이고 조합은 플레이어의 것이며 그 경계는 흐릿하다 |
| 플레이어가 만드는 것 — 사건 | Hitman | `상황 → 과정 → 사건`. 게임이 주는 것이 완성된 콘텐츠가 아니라 **재료와 규칙**일 수 있다 |
| 재료를 주는 것 ≠ 콘텐츠를 주는 것 | Hitman | 연출 10개는 콘텐츠 10개지만, 서로 엮이는 재료 10개는 **조합에서 값이 나온다.** 대신 통제를 포기하는 대가가 있다 |
| 예측 가능성은 계획의 전제조건이다 | Hitman | 동선이 시간표로 고정되어야 관찰이 자산이 된다. **무작위성을 넣을 자리와 넣지 말 자리를 가르는 기준** |
| 잠입 자원의 세 가지 형태 | Hitman | 안 보이는 **틈**(Shadow Tactics) / 깎이는 **게이지**(Dishonored) / 여기 있어도 되는 **자격**(Hitman) |
| 연주와 작곡 | Hitman | 자유도를 말할 때는 `무엇이 자유로운가`까지 적는다. 푸는 방법이 자유로운 것과 문제의 형태를 정하는 것은 다르다 |
| UX 문제는 제거 후보와 섞지 않는다 | Sleeping Dogs | UI 위치는 개선 항목이고, 정보 표시량은 **어디에서 읽게 할 것인가**의 선택이다. 두 목록을 섞으면 정작 지워도 되는 것을 못 찾는다 |

## 분석하면서 바뀐 생각들

기록으로 남길 가치가 있는 것은 결론보다 **판단이 바뀐 지점**이다.

| 게임 | 처음 생각 | 바뀐 생각 |
|---|---|---|
| Portal 2 | 포탈 건이 재미있는 건 순간이동이라는 SF적 장치 때문 | 공간 인식을 바꾸고 실험하게 만드는 장치라서 |
| Portal 2 | 스토리는 없어도 된다 | 퍼즐을 푸는 이유와 목적성을 부여한다 |
| Vampire Survivors | 성장 체감은 데미지 숫자에서 온다 | 화면 점유율과 시각적 영향력 확장에서 온다 |
| Vampire Survivors | 상자를 아껴 여는 건 그냥 내 습관 | 확률 공간을 조작하는 최적화 행동이었다 |
| Celeste | 대시는 빠르게 이동하는 기술 | 한 번 쓰면 조건까지 못 쓰는 제한 자원 |
| Celeste | 스피드런 기술은 고인물 꼼수 | 규칙을 극한까지 이해한 결과물 |
| Hollow Knight | 지도 시스템은 불편해서 없어도 된다 | 공간을 기억하게 만드는 탐험 메커닉이다 |
| Hollow Knight | 내가 막힌 건 게임 구조 문제 | 번역이 없던 플레이 환경의 문제였다 |
| Outer Wilds | 분석을 더 보충해야 한다 | 이 방법으로는 분석할 수 없다는 게 결론이다 |
| Papers, Please | 분기 인물 등장 시점을 모르는 건 단점 | 초회차엔 장점, 반복 플레이엔 아쉬움 |
| INSIDE | 병아리 디테일은 없어도 된다 | 플레이 필수는 아니지만 몰입을 만든다 |
| Slay the Spire | 얇은 덱이 그냥 좋은 것 | 좋은 카드를 더 자주 보기 위한 것 |
| Obra Dinn | 1비트 흑백은 없어도 되는 연출 | 정보량을 줄여 단서에 집중시키는 장치 |
| Baba Is You | 없어도 되는 요소를 못 찾은 건 내 분석이 부족해서 | 이 게임엔 그런 요소가 없을 수도 있다 |
| Factorio | 자동화 자체가 개발 의도 | 자동화는 수단이고, 내 설계가 작동하는 쾌감이 의도 |
| The Witness | 퍼즐의 재미를 전달하려는 게임 | 규칙을 발견하게 만드는 게임 |
| Among Us | 사보타지는 크루원을 분산시킨다 | 실제 메타에서는 오히려 뭉치게 만들었다 |
| Disco Elysium | 결과가 같은 선택지는 없어도 되는 요소다 | 결과 말고도 바뀌는 것이 있으면 살아 있는 선택이다 |
| Hades | 전투 스펙업 요소가 너무 많다 | 개수가 아니라 서로 다른 시간축을 담당하는 시스템이었다 |
| Hades | 플레이어가 빌드를 만든다 | 개발자가 깔아 둔 가능성의 공간 안에서 고르고 발견하는 것이다 |
| 완다와 거상 | 약점을 찾아 공격하는 것이 기믹이다 | 거상 하나가 통째로 기믹형 스테이지다 |
| 완다와 거상 | 긴 이동 시간은 없어도 되는 요소다 | 제거 대상은 이동이 아니라, 반복 플레이에서 같은 이동을 다시 시키는 구조다 |
| 완다와 거상 | 시네마틱 카메라는 지금 기준으로 제거 대상이다 | 문제는 카메라가 아니라 연출과 조작권이 충돌하는 상황이다 |
| Devil May Cry 5 | 플레이어는 화려한 콤보를 만든다 | 콤보가 아니라 자신의 플레이 스타일을 만든다 |
| Devil May Cry 5 | 없어도 되는 요소를 못 찾은 건 분석이 부족해서 | 개발사가 이미 지운 뒤였다. Baba Is You처럼 처음부터 없는 것과는 다른 경우다 |
| Devil May Cry 5 | 난이도 상승은 적의 체력과 공격력을 올리는 것 | 익힌 시스템을 더 높은 수준으로 쓰게 만드는 장치다 |
| Shadow Tactics | 잠입 전략 게임이다 | 실시간으로 진행되는 퍼즐 게임에 가깝다. 승패는 실행이 아니라 계획에서 갈린다 |
| Shadow Tactics | 설명되지 않는 발각은 적 AI의 변칙적인 행동이다 | 원인을 설명할 수 없다면 메커닉이 아니라 결함으로 분리해야 한다 |
| Shadow Tactics | 개발사가 장르를 잘 안다는 정보는 분석에 도움이 된다 | 관찰 이전에 들어오면 재료가 아니라 편견이 된다 |
| Katana ZERO | 액션 게임과 퍼즐 게임은 다른 장르다 | `관찰 → 계획 → 실행 → 실패 → 수정`이 있으면 전투도 퍼즐이 된다 |
| Katana ZERO | 즉사 시스템은 난이도를 높이는 장치다 | 실패를 빠르게 반복시켜 학습으로 바꾸는 장치다 |
| Katana ZERO | 시간 제한은 클리어 조건이다 | 기다리는 플레이를 지워서 공격적인 해법만 남기는 장치다 |
| Katana ZERO | Coffin Head는 없어도 되는 요소다 | 그렇게 판단한 근거가 기능 분석이 아니라 취향이었다. 결론을 `보류`로 남겼다 |
| Monster Hunter: World | 반복 사냥은 소재를 모으기 위한 파밍 루프다 | 파밍 루프 위에 학습 루프가 겹쳐 있고, 재미는 주로 뒤쪽에서 나온다 |
| Monster Hunter: World | 플레이어가 만드는 것은 장비와 빌드다 | 장비 조합 · 사냥 방법 · 몬스터에 대한 지식이며, **세 번째가 가장 크다** |
| Monster Hunter: World | 선택지가 많으면 플레이어가 창의적으로 만든다 | 최적해가 검색되는 영역에서는 만들지 않고 따라간다 |
| Monster Hunter: World | 조라 마그다라오스는 컨셉이 좋으니 성립한다 | 컨셉에 필요한 요소가 오히려 핵심 재미를 밀어낼 수 있다 |
| Sleeping Dogs | 오픈월드는 맵이 넓은 게임이다 | 그 공간을 돌아다닐 이유를 만든 게임이다 |
| Sleeping Dogs | 부가 활동은 게임에 영향을 안 주니 없어도 된다 | 핵심 루프에는 불필요하지만 공간을 살아 있게 만드는 기능이 있다 |
| Sleeping Dogs | 적 체력 표시가 없는 것은 없어도 되는 요소다 | 정보를 지운 것이 아니라 출처를 UI에서 적의 모션으로 옮긴 것이다 |
| Sleeping Dogs | 플레이어는 어느 게임에서든 무언가를 만든다 | 이 게임에서는 그것이 뚜렷하지 않고, 대신 경험이 축적된다 |
| Dishonored | 스텔스 게임이니 은신이 정답이다 | 전투도 선택지이며, 플레이어가 대가를 계산해서 스스로 잠입으로 옮겨간 것이다 |
| Dishonored | 오브젝트 상호작용이 많은 것은 없어도 되는 요소다 | 기능은 있다. 제거가 아니라 **범위 조정**의 문제다 |
| Hitman | 히트맨의 자유도는 맵이 넓어서 나온다 | 제공된 시스템 사이의 **관계를 조합할 수 있어서** 나온다 |
| Hitman | 플레이어가 만드는 것은 빌드나 루트다 | 상황과 사건 자체가 될 수 있다 |

## 스스로 점검하는 질문

분석을 마쳤을 때 아래 질문에 답할 수 있는지 확인한다.

- 이 게임의 핵심 경험을 한 문장으로 말할 수 있는가?
- 메커닉을 나열한 것에서 끝나지 않고 감정까지 연결했는가?
- `행동 → 규칙 → 결과 → 감정` 중 '결과' 칸을 비워두지 않았는가?
- 핵심 자원을 특정했는가?
- 내 개인 취향과 UX 문제를 구분했는가?
- 개발 의도와 내 경험을 구분해서 적었는가?
- **어디까지가 확인된 사실이고 어디부터가 내 추론인지 구분해서 적었는가?**
- **분석을 시작하기 전에 이미 알고 있던 정보가 내 관찰을 기울게 하지 않았는가?**
- 설명되지 않는 현상을 설계로 해석하지는 않았는가?
- **제거 후보라고 판단한 요소가, 게임플레이 밖의 기능(세계관 · 분위기 · 캐릭터성)을 맡고 있지는 않은가?**
- **이 게임의 반복은 플레이어를 성장시키는가, 시간을 소비시키는가?**
- **`없어도 돌아가는가`가 아니라 `없애면 어떤 경험이 사라지는가`를 물었는가?**
- **이 게임이 주는 것은 완성된 콘텐츠인가, 플레이어가 조합할 재료인가?**
- 처음 생각이 분석 중에 바뀐 지점을 기록했는가?
- **플레이어가 이 게임에서 만들어내는 것**을 한 단어로 말할 수 있는가?
- 이 게임을 이 방법으로 분석하는 것이 적절했는가?
